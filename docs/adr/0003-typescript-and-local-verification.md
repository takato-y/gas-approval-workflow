## 状況

GAS のコードは Google の環境でしか動かず、エディタ上の手動確認だけではトークンの改ざん・二重承認などの異常系を網羅できない。最初は JavaScript で書き始めたが、申請・トークン・設定の項目が多く、列の位置や項目名の取り違えが起きやすい。

## 決定

- GAS のソースは TypeScript で書き、`tsc` で `dist/` に出力して clasp で送る。import/export は使わず、GAS のグローバル空間の作法（末尾 `_` で非公開）をそのまま守る。
- 承認経路・トークン・状態遷移・督促対象の選定は、Google のサービスを呼ばない純粋な関数に分ける。暗号処理（HMAC の計算）は関数として引数で受け取り、Google のサービスに直接依存しない。
- テストはビルド済みの `dist/*.js` を Node.js の `vm` で読み込み、GAS のサービスを代替部品（モック）に差し替えて動かす（送るファイルと同じものを検証する）。
- 承認画面は HTML・CSS・画面側の JavaScript のテンプレートに分け、画面側のスクリプトも最小限の DOM の代替部品で動かして確かめる。
- テストとサンプルデータ作成のコマンドも TypeScript で書き、Node.js の型の除去機能で直接実行する。

## 理由

- 型によって、シートの列と項目の対応・関数の引数の取り違えをビルド時に見つけられる。
- 純粋な関数は Google 環境なしで境界値・異常系まで機械的に確認できる。
- `dist` を検証対象にすることで、「TypeScript では正しいが出力が GAS で動かない」差を減らせる。

## 影響

- 代替部品は実物の一部しか再現しないため、Google 環境での確認（[05_テスト仕様書](../05_テスト仕様書.md) の3章）は別に必要である。
- テストの実行には Node.js 22.18 以上が必要になる。
